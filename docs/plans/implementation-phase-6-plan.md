**This planning task's Scope Lock:** this file only.

## Objective and boundaries

Plan independently approvable increments from the disabled Phase 5 adapter to a local, manually triggered, fail-closed analysis capability. Phase 6 remains local and single-user. No import, startup, status request, technical `AISettings.enabled` switch, credential presence or smoke success authorizes a commercial provider call. Commercial authorization is separate, process-local, revocable and OFF at every start. No scheduler, automatic analysis, external mutation or new AI data category is included. The Phase 5 minimization, strict schema, evidence checks, no attachments, no tools, `store=false`, prompt-injection boundary and existing approval/revalidation/audit rules remain binding.

No new dependency, migration, provider-telemetry table, owner column or persistent authorization/smoke state is planned. Normal pytest is entirely offline. The optional live synthetic smoke (6F) and commercial-data activation (6G) are **separate later approvals**, not outcomes of this plan. Global commercial processing remains blocked absent the user's explicit later processing-mode decision; an EU-looking URL or smoke success is insufficient.

## Ownership decision replacing the former STOP

D12/D13 approve an exclusive Windows `CreateFileW` handle with zero sharing, implemented via stdlib/`ctypes` and strongly held by the actual serving worker for the whole operational lifetime. The sidecar path derives from the canonical absolute SQLite file identity, never from port, PID or working-directory text. Unsupported/non-file SQLite URL, path ambiguity, unsuitable storage, lock-location/access failure or exclusive-open conflict fails startup closed. The handle is non-inheritable. A stale sidecar filename proves nothing. The reloader parent never counts as owner; normal operation requires one worker and forbids `--reload`, multiple workers and `--lifespan off`. Development `--reload` is allowed only with operational AI/manual commercial execution unavailable. Direct Uvicorn import or alternative entry points cannot bypass the provider-facing ownership check.

Startup order: construct inert app → worker lifespan acquires handle → controlled, idempotent recovery transaction → manual route may become available. Shutdown order: reject new work → allow already-sent call to finish or explicitly cancel and observe termination of in-process work → release handle. A new process may recover only after it actually acquires exclusivity; delayed OS release is refusal, not a timeout override. Every real provider attempt/retry checks live ownership plus the appropriate authorization capability. A commercial attempt additionally requires the independent process-local commercial gate. The fixed-literal smoke path is a distinct one-shot synthetic capability under the same operational lock; it cannot accept commercial input or authorize the commercial gate.

**First-deployment boundary:** the lock cannot attest that a pre-lock process is dead. Before deploying the recovery-enabled build, the operator must stop and verify all pre-lock instances/provider calls are quiescent and confirm there are no unresolved legacy `reserved` rows. Any legacy reservation encountered at cutover blocks automatic recovery and requires a separately approved quiescent resolution rule; the new lock alone does not authorize sweeping it. Only after this documented cutover invariant holds can a later startup treat inherited `reserved` rows as belonging to a prior lock-aware instance. No age-only sweep is allowed. If the cutover invariant cannot be enforced in the eventual operational procedure, STOP and revisit persistent per-run ownership.

## Risks and STOP criteria

The key risks are accidental provider calls via direct adapter construction, a child without a lock, reload/worker bypass, releasing ownership while a request remains in flight, an incorrect canonical DB identity, sweeping legacy reservations at first rollout, forged localhost POSTs, key disclosure and treating a synthetic smoke as consent. Fail closed on each. If a viable implementation needs a schema change, new dependency, unapproved persistent marker/credential mechanism, different startup mode, or an unresolved choice that changes security semantics, **STOP before code** and request a new decision. The approved single-instance design must be verified by offline Windows tests, not merely asserted by this plan.
