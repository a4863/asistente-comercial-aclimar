## 3. Current boundary and relevant inheritance

The adapter builds a fixed synthetic smoke input, JSON-encodes it before the SDK call, checks its UTF-8 size, and maps local `ValueError`/`UnicodeError` there to `invalid_input`. It then calls `client.responses.create(**request_kwargs)`. That call's exception handler preserves exact `JSONDecodeError -> provider_response_json_failure` and exact `ValueError -> provider_sdk_value_failure`, then residual `ValueError` subclasses become `provider_value_subclass_family`. The response parser after a successful SDK return is a different boundary and maps malformed analysis output to `invalid_output`.

Known relationships checked without reflecting the live exception: `UnicodeError` (including `UnicodeEncodeError`/`UnicodeDecodeError`) descends from `ValueError`; `idna.IDNAError` descends from `UnicodeError`; `pydantic.ValidationError` is the `pydantic_core.ValidationError` class and descends from `ValueError`; `pydantic_core.PydanticSerializationError` also descends from `ValueError`. In contrast, `httpx2.InvalidURL` is **not** a `ValueError` subclass. Malformed input to the installed `jiter.from_json` and `pydantic_core.from_json` produced **exact** `ValueError` in local synthetic checks, so those particular errors would have taken the existing exact-value code, not the seventh result. The standard `json.loads` malformed-JSON syntax path produced exact `JSONDecodeError`, already separately classified.

## 5. Local no-network reproductions

All checks used Python `-B`, an API key consisting only of synthetic test text, the current fixed smoke request, `httpx2.MockTransport`, `trust_env=False`, and no external socket. Output was restricted to predetermined case labels, fixed adapter codes, dispatch counts, and boolean class-family checks; no raw exception text, class identity of a caught error, body, URL, headers, or secret was emitted.

- Mock 200 `application/json` with one invalid UTF-8 byte → `provider_value_subclass_family`, one mock dispatch. Source path `Response.json() -> json.loads(bytes)` explains the Unicode descendant without requiring a live probe.
- Mock 200 `{}` with test-only strict SDK validation → existing `provider_response_validation_failure`, one mock dispatch. Strict mode was only a diagnostic test setting; production behavior was not changed.
- Injected Pydantic validation and Pydantic-core serialization errors through a no-send transport → residual `provider_value_subclass_family`, one mock dispatch each. Injection demonstrates catch behavior only; it is **not** evidence those errors arise naturally for the fixed request.
- Local invalid JSON through `jiter.from_json` and `pydantic_core.from_json` → exact plain ValueError; invalid JSON syntax through stdlib `json.loads` → exact JSONDecodeError. These observations exclude those tested parser-error shapes from explaining the seventh *residual* code.

## 6. Bounded recommendation, precedence, and scope

Recommend **one** new fixed code, conceptually `provider_unicode_error_family`, for `isinstance(error, UnicodeError)` **after** every existing exact JSON/ValueError and all higher-priority OpenAI/HTTP/OS branches but **before** the existing residual `isinstance(error, ValueError)` branch. Keep `provider_value_subclass_family` unchanged as the fallback for all other ValueError subclasses, including any raw Pydantic validation/serialization errors. This is a meaningful partition because the Unicode path is naturally reproduced with the exact fixed request and a no-network 200 response. It neither names the actual live class nor claims where malformed bytes originated. `idna.IDNAError` would also match by inheritance if it escaped abnormally; the code must remain **Unicode family**, not “bad provider JSON” or “IDNA/URL failure.” Exact `JSONDecodeError` and exact `ValueError` must keep their existing codes. No `provider_value_other_family` alias is needed: it would merely rename the existing fallback without adding information.

Do **not** add a Pydantic-specific production import or category on present evidence. Its normal response-validation route is already wrapped; the fixed request does not demonstrate a serialization route. If later evidence establishes an unwrapped Pydantic path, analyze it separately. No dynamic class name/module/MRO, hash/fingerprint, `str`/`repr`/`args`, cause/context, provider body/message, request/URL/header, or nested exception inspection is permitted.

Proposed separately approved correction Scope Lock: **IN SCOPE** `app/integrations/openai_analysis.py` (one built-in family branch), `test/test_openai_analysis.py` (offline real-SDK invalid-byte and synthetic inheritance/precedence/no-leak tests), `app/integrations/ai_smoke_cli.py` (one literal allowlist addition), `test/test_ai_smoke_cli.py` (bounded output/fallback tests). **OUT OF SCOPE:** all other files and external systems. **RESTRICTIONS:** no new dependency/import, model/endpoint/schema/payload/timeout/retry change, keyring/gate/route/config/database change, live smoke, transport instrumentation, or raw diagnostic content.
