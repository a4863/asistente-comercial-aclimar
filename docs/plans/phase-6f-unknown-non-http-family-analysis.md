## Bounded recommendation and precedence

A **six-code** family partition is defensible for a separate plan. Each output must be a fixed literal chosen from approved `isinstance` checks; none may contain an actual class name or imply a confirmed root cause:

1. `provider_openai_error_family`: residual `openai.OpenAIError` after all existing typed OpenAI branches.
2. `provider_http_client_error_family`: residual `httpx2.RequestError` after SDK timeout/connection/status handling; do not use `HTTPError` broadly.
3. `provider_os_error_family`: `OSError`, including SSL descendants; no network-cause claim.
4. `provider_value_subclass_family`: residual `ValueError` descendants, including Pydantic and Unicode; exact `JSONDecodeError` and exact `ValueError` retain their existing codes. This avoids a new direct Pydantic import/dependency while separating this broad family from other Python internals.
5. `provider_python_internal_family`: residual `TypeError`/`RuntimeError` descendants and `AttributeError`, `LookupError`, or `AssertionError`. It signals a Python processing family only, not an SDK bug or pre-send failure.
6. `provider_exception_group_family`: outer `ExceptionGroup` only; do not traverse nested members.

Order: retain all current HTTP/timeout/connection and five exact-class checks **unchanged**; then residual OpenAI family, HTTP-client request family, OS family, ValueError-subclass family, Python-internal family, and outer ExceptionGroup; finally the existing `provider_non_http_failure`. A specific OpenAI/HTTP classification must precede general Python categories. This keeps all current retry/transient flags and exact-class behavior intact. All new family codes should be non-retryable unless separate evidence justifies a policy change; this task does not authorize one. Raw `httpcore2` and unrecognized `Exception` remain in the fixed generic fallback. An `ExceptionGroup` with a non-`Exception` member is outside the adapter's current `except Exception` contract and must not be swept into a broader `BaseException` catch.

This vocabulary can materially narrow an authorized *future* synthetic live failure to SDK-defined, residual HTTP-client, OS, value-subclass/validation/encoding, Python-internal, or grouped-exception territory. It cannot prove pre/post-dispatch, provider versus intermediary, or the exact exception, and may still return the generic fallback. No one-time class-name fingerprint, MRO dump, hash, raw text, cause/context, or nested-group inspection is necessary or acceptable here. If a later live attempt still yields generic fallback, **STOP** for a separate decision instead of broadening disclosure or adding arbitrary categories.
