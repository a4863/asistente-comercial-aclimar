## Failure boundary and recommendation

Currently the `try` around `client.responses.create(...)` also evaluates `response_schema()` and the inline `text` object. Any exception from that local evaluation, SDK transformation/request construction, transport, or SDK response handling reaches the same catch. The existing typed timeout/connection/HTTP branches are handled first; remaining exceptions become `provider_non_http_failure`. The previous live result therefore does not identify the failing phase. A successful no-send call makes a **static** kwarg/signature or static-schema failure unlikely for this exact synthetic path, but cannot exclude a different runtime value, transport-layer non-HTTP exception, SDK response parsing, or another local failure. Do not change model, endpoint, payload, schema semantics, timeout, or retry policy on this evidence.

For a future correction, evaluate `response_schema()` and assemble the immutable format/request kwargs in a separate bounded local `try` **before** the SDK invocation, mapping any unexpected local construction exception to a fixed `request_schema_failure` code. Keep SDK call errors in the existing catch: preserve all typed HTTP, timeout, connection, and retry mappings, and map the remaining class only to `provider_non_http_failure` (or a carefully named `provider_sdk_local_failure` if the plan can prove that name does not imply pre-HTTP causation). A non-HTTP exception from `responses.create()` is not necessarily pre-HTTP: response parsing can also fail after a mocked or real HTTP response. Do not label it `sdk_request_validation_failure` without a trustworthy dispatch marker. Exact pre-dispatch versus post-dispatch attribution would require a separate, explicitly approved transport-boundary design; it is not justified by this analysis. No raw exception message/type, request text, response body, key, or SDK metadata should be surfaced.

The current smoke CLI has an explicit allowlist. To expose `request_schema_failure` as `smoke_failed:request_schema_failure` rather than collapsing it to `smoke_failed`, the **proposed exact Scope Lock is four files**: `app/integrations/openai_analysis.py`, `test/test_openai_analysis.py`, `app/integrations/ai_smoke_cli.py`, and `test/test_ai_smoke_cli.py`.
